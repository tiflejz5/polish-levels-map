# Polish Levels Map

A static web app for learning Polish (A1–C2), explained in English. Ported from `english-levels-map`; the two projects are independent.

> **Work in progress (stage 4).** The interface is English (spec 04), the Polish language layer is in place (spec 05), and the exercise engine runs every item type on Polish data, with the new "Fill the table" type and the full content validators (stage 4). The full README is written in stage 7. The plan is in `docs/plan/` (start with `docs/plan/00-READ-ME.md`).

## Run

Open `index.html` (from disk or any static server, for example GitHub Pages). No build step is needed to run it: plain `<script>` files, one global `window.LM`, no modules, no `fetch()`.

## Build and checks

```
npm run build        # validate → regenerate data/ from content/ → stamp ?v=N; --bump raises the version
npm run validate     # content validators (tools/validate-*.js, spec 06 E11); --root docs/plan checks the plan examples
npm run validate:plan  # the same on docs/plan (syllabus + examples; agrees with docs/plan/scripts/validate_plan.py)
npm run strip-keys -- <files or folders>   # items without the key, for the solver subagent (spec 10 §4)
npm test             # unit tests for pure logic
npm run check:lang   # no Polish text or language facts outside js/lang.js, js/config.js and content/; false positives in tools/check-lang-allow.json
npm run contrast     # WCAG contrast of the design tokens
npm run e2e          # browser smoke tests (skipped without Playwright)
npm run assets       # copy fonts, icons and GSAP from node_modules into assets/ (after npm install)
```

## Layout

```
content/   sources: syllabus.json (source of truth for ids), levels.json, pages/, quizzes/, exercises/, decks/, lab/, tests/
data/      GENERATED by tools/build.js (committed; never edit by hand)
js/        app code; js/config.js (LM.APP) and js/lang.js (LM.lang) hold everything Polish-specific
tools/     build.js + build/*.js, validate.js + validate-*.js, strip-keys.js, tests.js, contrast.js, e2e.js, assets.js
```

## Syllabus, levels, trail, exams

- `content/syllabus.json` is the only list of levels, units, categories and topics (`LM.syllabus`). The checklist is the list of topics: `progress[<topic id>] = true`. The level page groups the topics by category.
- `content/levels.json` sets each level to `available` or `soon`. A soon level shows its planned topics (no links, no checkboxes, no final test or cheat sheet), is dimmed on the trail, is not searched and does not count on Today. A topic of an available level without a page shows "This topic is being written".
- The trail is generated by the build: one stop per topic and one checkpoint per unit (`data/trail.js`). `content/trail-overrides.json` (optional) renames stops or changes checkpoint sizes.
- Exams live under `#/exams/<id>` and come only from `content/exams/registry.json` (empty until stage E, so the sidebar group is hidden). `tools/fixtures/exam-demo` is a made-up exam that keeps the exam code under unit and e2e tests.

## Language layer (stage 3, spec 05)

- **Rules** live in `js/lang.js` (`LM.lang`: marks, folding, normalizing, word count, the `isTarget` fallback, abbreviations) and **values** in `js/config.js` (`LM.APP`: voices, letters of the character bar). Every other file reads them from there; `npm run check:lang` fails on hard-coded language codes, Polish abbreviations or function words, the deleted English rules, and the Web Speech API outside `js/speech.js`.
- **Answers.** `LM.exLogic.match` checks every typed answer (exercises and flashcards): exact → accents only → wrong ending → typo → word diff. Near misses score 0 with a hint and the closest answer. The learning setting "Accept answers without accents" counts accents-only answers (the reminder stays; the stats show them as a small separate number).
- **Character bar** (`js/charbar.js`): under every Polish input (`data-charbar`); Shift or a long press gives the capital; on a desktop Alt + letter cycles the marked forms.
- **Speech** (`js/speech.js`, `LM.speech`): one implementation, pl-PL voices only. Without a Polish voice the listen buttons are hidden, listening items show the transcript, dictation is skipped, and Learning settings say how to add a voice.
- **Markup.** In Markdown, `*italics*` (Polish only — English emphasis is `**bold**`), the cells of a table column headed "Polish" and blockquotes get `lang="pl"`. Those table rows and blockquotes get a listen button (S reads the focused one). "Add to My words" appears only inside `lang="pl"` text.
- **Fixtures** for the language tests are in `tools/fixtures/lang/`.

## Exercises and validators (stage 4)

- **Item types** (`js/exercise-logic.js`, view in `js/exercise-engine.js`): multiple choice, put in order, find the mistake, short answer, fill the gaps, match pairs, rewrite the sentence, translate, dictation and **fill the table** (`paradigm`, spec 06 E6): 3–8 labelled cells, `given` cells shown filled, a point per cell. A cell label that is a case id (`genitive`) is shown as "Genitive (kogo? czego?)" from `LM.lang.cases`. Two columns from 480 px (Tab goes down a column), one below; at most two per final test.
- **Polish data.** Put in order keeps „quotes” on their words, leaves dashes out of the tiles, lower-cases the first word unless it is a name (capitalised inside another accepted order, or `keepCapital: true`) and ignores punctuation. Speech reads no English instructions, glosses or lemma hints. Free word order and dropped pronouns are content rules: list every natural order (spec 05 §3).
- **Tests (E10).** Placement skills are grammar, vocabulary and reading (cases and verbs count as grammar); final tests draw in proportion to the syllabus categories.
- **Validators** (`tools/validate.js` + `validate-pages`, `-exercises`, `-tests`, `-decks`, `-lab`, `-cheatsheets`, `-phrases`, `-items`, `-lib`): every rule of `validate_plan.py`, the kept-format rules of the original validators and the E11 heuristics (subject pronoun, speaker gender, Polish alphabet, long text without diacritics). Until the first content stage an incomplete available level and a short placement pool are warnings (`STRICT_COMPLETE` in `tools/validate.js`). `npm test` checks that Node and Python flag the same places on a broken fixture (`tools/fixtures/validate/`).

## Routes

`#/` home · `#/today` · `#/trail` · `#/a1` … `#/c2` level page · `#/a1/<category>-<slug>` topic page · `#/a1/test`, `#/a1/cheatsheet` · `#/placement` · `#/review`, `#/review/decks[/…]`, `#/review/mistakes`, `#/review/words`, `#/review/session[?only=mistakes|weak|decks|deck:<id>]` · `#/practice`, `#/practice/set/<id>`, `#/practice/mix/<id>`, `#/practice/session`, `#/practice/weak[/<topic>]` · `#/lab[/…]` · `#/writing`, `#/writing/models/<exam>/<id>`, `#/writing/phrases[/<group>]` · `#/stats`, `#/notes` · `#/exams/<id>[/…]`. There are no redirects from the original app's routes; any other address shows "Page not found".

## Version stamp

`package.json` → `"lmVersion"` is the only source. The build writes it as `?v=N` on every local `<script>`/`<link>` in `index.html` and as `LM.VERSION` in `js/config.js`; `LM.loadModule(path)` adds it to files loaded on demand.

## Storage

Every key starts with `plm.` (the owner's apps share one origin on GitHub Pages; keys of the original app, `elm_*`, are never read or written). The key registry in `js/profile-data.js` drives export, import, reset and profile deletion.

| Key | Scope |
|---|---|
| `plm.theme`, `plm.sidebar` | device; not exported, kept by reset |
| `plm.ui`, `plm.search-recent` | device; not exported, cleared by reset |
| `plm.profiles` | profile list with progress (`{ version: 1, activeId, profiles: [{ id, name, progress }] }`) |
| `plm.journal`, `plm.activity`, `plm.placement`, `plm.celebrated`, `plm.exercises`, `plm.attempts`, `plm.autojournal`, `plm.prefs`, `plm.notes`, `plm.exams`, `plm.speaking`, `plm.finals`, `plm.phrases` | learning data of all profiles (`{ version: 1, profiles: { <id>: … } }`) |
| `plm.cards.<profileId>`, `plm.trail.<profileId>` | flashcards and trail, one key per profile |

A broken stored value is kept once as `<key>.corrupt-backup`; a broken profile list opens a recovery screen instead.

Backup file: `polish-levels-map-YYYY-MM-DD.json` = `{ app: "polish-levels-map", kind: "backup", version: 1, exportedAt, data: { profiles, learning, cards, trail } }`. A file of another app is refused.
