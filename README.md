# Polish Levels Map

A static web app for learning Polish (A1–C2), explained in English. Ported from `english-levels-map`; the two projects are independent.

> **Work in progress (stage 2).** The interface is English (spec 04). The Polish language layer comes in stage 3; the full README is written in stage 7. The plan is in `docs/plan/` (start with `docs/plan/00-READ-ME.md`).

## Run

Open `index.html` (from disk or any static server, for example GitHub Pages). No build step is needed to run it: plain `<script>` files, one global `window.LM`, no modules, no `fetch()`.

## Build and checks

```
npm run build        # validate → regenerate data/ from content/ → stamp ?v=N; --bump raises the version
npm run validate     # content validators (stage 1: structural rules; item-level rules arrive in stage 4)
npm test             # unit tests for pure logic
npm run check:lang   # no Polish text or language facts outside js/lang.js and js/config.js; false positives in tools/check-lang-allow.json
npm run contrast     # WCAG contrast of the design tokens
npm run e2e          # browser smoke tests (skipped without Playwright)
npm run assets       # copy fonts, icons and GSAP from node_modules into assets/ (after npm install)
```

## Layout

```
content/   sources: syllabus.json (source of truth for ids), levels.json, pages/, quizzes/, exercises/, decks/, lab/, tests/
data/      GENERATED by tools/build.js (committed; never edit by hand)
js/        app code; js/config.js (LM.APP) and js/lang.js (LM.lang) hold everything Polish-specific
tools/     build.js + build/*.js, validate.js, tests.js, contrast.js, e2e.js, assets.js
```

## Syllabus, levels, trail, exams

- `content/syllabus.json` is the only list of levels, units, categories and topics (`LM.syllabus`). The checklist is the list of topics: `progress[<topic id>] = true`. The level page groups the topics by category.
- `content/levels.json` sets each level to `available` or `soon`. A soon level shows its planned topics (no links, no checkboxes, no final test or cheat sheet), is dimmed on the trail, is not searched and does not count on Today. A topic of an available level without a page shows "This topic is being written".
- The trail is generated by the build: one stop per topic and one checkpoint per unit (`data/trail.js`). `content/trail-overrides.json` (optional) renames stops or changes checkpoint sizes.
- Exams live under `#/exams/<id>` and come only from `content/exams/registry.json` (empty until stage E, so the sidebar group is hidden). `tools/fixtures/exam-demo` is a made-up exam that keeps the exam code under unit and e2e tests.

## Routes

`#/` home · `#/today` · `#/trail` · `#/a1` … `#/c2` level page · `#/a1/<category>-<slug>` topic page · `#/a1/test`, `#/a1/cheatsheet` · `#/placement` · `#/review`, `#/review/decks[/…]`, `#/review/mistakes`, `#/review/words`, `#/review/session[?only=mistakes|weak|decks|deck:<id>]` · `#/practice`, `#/practice/set/<id>`, `#/practice/mix/<id>`, `#/practice/session`, `#/practice/weak[/<topic>]` · `#/lab[/…]` · `#/writing`, `#/writing/models/<exam>/<id>`, `#/writing/phrases[/<group>]` · `#/stats`, `#/notes` · `#/exams/<id>[/…]`. There are no redirects from the original app's routes; any other address shows "Page not found".

## Version stamp

`package.json` → `"lmVersion"` is the only source. The build writes it as `?v=N` on every local `<script>`/`<link>` in `index.html` and as `LM.VERSION` in `js/config.js`; `LM.loadModule(path)` adds it to files loaded on demand.

## Storage

Every key starts with `plm.` (the owner's apps share one origin on GitHub Pages; keys of the original app, `elm_*`, are never read or written). The key registry in `js/profile-data.js` drives export, import, reset and profile deletion.

| Key | Scope |
|---|---|
| `plm.theme`, `plm.sidebar` | device; not exported, kept by reset |
| `plm.ui`, `plm.search-recent` | device; not exported, cleared by reset |
| `plm.profiles` | profile list with progress (`{ version: 1, activeId, profiles: [{ id, name, progress }] }`) |
| `plm.journal`, `plm.activity`, `plm.placement`, `plm.celebrated`, `plm.exercises`, `plm.attempts`, `plm.autojournal`, `plm.prefs`, `plm.notes`, `plm.exams`, `plm.speaking`, `plm.finals`, `plm.phrases` | learning data of all profiles (`{ version: 1, profiles: { <id>: … } }`) |
| `plm.cards.<profileId>`, `plm.trail.<profileId>` | flashcards and trail, one key per profile |

A broken stored value is kept once as `<key>.corrupt-backup`; a broken profile list opens a recovery screen instead.

Backup file: `polish-levels-map-YYYY-MM-DD.json` = `{ app: "polish-levels-map", kind: "backup", version: 1, exportedAt, data: { profiles, learning, cards, trail } }`. A file of another app is refused.
