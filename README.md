# Polish Levels Map

A free, static web app for learning **Polish from A1 to C2, explained in English**. Six levels are six lands on a map (Meadow, Forest, Hills, Lake, Mountains, Summit). Each level is a list of topics from a fixed syllabus; each topic has a page, a short quiz on the trail and exercise sets. Around them: a placement test, final tests, flashcards with spaced review, a mistake log, My words, notes, search, stats and the **Case Lab** (all seven cases on one map).

No accounts, no tracking, no server: progress is stored only in the browser (`localStorage`), with export and import of a backup file.

Ported from english-levels-map (Polish UI, teaches English); the two projects are independent.

## Run

Open `index.html`. That is all: from disk (`file://`), from any static server or from GitHub Pages (`https://tiflejz5.github.io/polish-levels-map/`). No build step is needed to *run* the app:

- plain `<script src>` files and one global `window.LM`; no modules, no `fetch()`, no framework, no CDN;
- `content/` holds the sources (JSON and Markdown), `data/` the generated `.js` files (committed); big ones are loaded on demand with a `<script>` tag, so `file://` works.

Node (≥ 20) is needed only to build, validate and test.

```
npm install          # once: fonts, icons, GSAP and Playwright for the browser tests
npm run build        # after any change in content/
```

## Commands

```
npm run build        # validate → regenerate data/ from content/ → search index → stamp ?v=N in index.html; --bump raises the version
npm run validate     # all content validators (tools/validate-*.js)
npm run validate:plan  # the same rules on docs/plan (syllabus + examples)
npm test             # unit tests for the pure logic (no DOM)
npm run check:lang   # fails on Polish text or language facts outside js/lang.js, js/config.js and content/
npm run contrast     # WCAG contrast of every token pair in both themes + the accent palette check
npm run e2e          # browser smoke tests (Playwright + Chrome/Edge; skipped when missing)
npm run assets       # copy fonts, icons and GSAP from node_modules into assets/ (after updating those packages)
npm run strip-keys -- <files or folders>   # items without the answer key, for the solver review (spec 10)
node tools/cheatsheets-pdf.js            # print every cheat sheet on A4 and US Letter; fails above one page
```

Every stage ends with `build`, `validate`, `test`, `check:lang`, `contrast` and `e2e` green.

## Storage

Every key starts with `plm.`. All the owner's apps share one origin on GitHub Pages, so keys of other apps (`elm_*` and `elm.<id>.*` of english-levels-map, `slm.` and any other prefix) are never read, written, exported or cleared. Every access is inside `try/catch`; with storage blocked (private mode) a banner says so and the app works until the tab closes. The key registry in `js/profile-data.js` drives export, import, reset and profile deletion.

| Key | Content | Scope |
|---|---|---|
| `plm.theme` | `"auto"`, `"light"`, `"dark"` | device; not exported, kept by reset |
| `plm.sidebar` | `{ version: 1, pinned }` | device; not exported, kept by reset |
| `plm.ui` | `{ levelId }` (the last level page; convenience only) | device; not exported, cleared by reset |
| `plm.search-recent` | recent searches | device; not exported, cleared by reset |
| `plm.profiles` | `{ version: 1, activeId, profiles: [{ id, name, progress: { <topic id>: true } }] }` | profiles and “I know this” |
| `plm.journal`, `plm.activity`, `plm.placement`, `plm.celebrated`, `plm.exercises`, `plm.attempts`, `plm.autojournal`, `plm.prefs`, `plm.notes`, `plm.exams`, `plm.speaking`, `plm.finals`, `plm.phrases` | `{ version: 1, profiles: { <id>: … } }` | learning data of every profile |
| `plm.cards.<profileId>` | flashcard state, user decks (My mistakes `u-mistakes`, My words `u-words`) | one key per profile |
| `plm.trail.<profileId>` | trail stops done | one key per profile |

A broken stored value is kept once as `<key>.corrupt-backup`; a broken profile list opens a recovery screen.

**Backup file** `polish-levels-map-YYYY-MM-DD.json` = `{ app: "polish-levels-map", kind: "backup", version: 1, exportedAt, data: { profiles, learning, cards, trail } }`. A file of another app is refused and nothing changes.

## Content and data formats

Full formats and quality rules: `docs/plan/spec/07-content-model.md`; gold-standard samples in `docs/plan/examples/` (they pass the validators). Everything in `content/` is original writing (no copying from textbooks, exam papers or websites).

| Source | Format | Built into |
|---|---|---|
| `syllabus.json` | `levels[] → { id, land, goal, units[] → { id, title, topics[] → { id, category, title, example } } }`. **The only list of topics; ids are frozen** (they are page ids, checklist ids, trail stops and storage keys). | `data/syllabus.js`, `data/trail.js` |
| `levels.json` | `{ "A1": "available", "A2": "soon", … }` | `data/syllabus.js` |
| `home.md` | the home page (Markdown); its “Status” column is filled from `levels.json` | `data/pages.js` |
| `pages/<level>/<category>-<slug>.md` | topic page: front matter `id, level, category, title, summary`, then the fixed section headings of spec 07 §1 | `data/pages.js` |
| `summaries/<level>.md`, `cheatsheets/<level>.md` | level summary, one-page cheat sheet | `data/pages.js` |
| `quizzes/<level>/<topic id>.json` | trail quiz: exactly 4 items, `passScore: 3` | `data/quizzes-<level>.js` (lazy) |
| `exercises/<topic id>-<n>.json` + `exercises/topics.json` (topic → sets) + `mixes.json` | sets of 8–12 items: multiple choice, put in order, find the mistake, short answer, fill the gaps, match pairs, rewrite, translate, dictation, fill the table | `data/sets/<id>.js` (lazy), `data/sets-index.js` |
| `tests/placement.json` | `{ version, questions[] }`, adaptive, skills grammar / vocabulary / reading | `data/placement.js` (lazy) |
| `tests/final-<level>.json` | `{ id, level, draw, passPercent, items[] }`, drawn in proportion to the syllabus categories | `data/final-<level>.js` (lazy) |
| `decks/index.json` + `decks/<id>.json` | flashcards: `basic` or `cloze` (`{{answer}} (lemma)`), `en`, `level`, `tags` | `data/decks-index.js`, `data/decks/<id>.js` (lazy) |
| `lab/cases.json`, `models.json`, `trees.json`, `aspect.json` | Case Lab: case cards, model phrases (all 14 forms), decision trees, the aspect strip (spec 09) | `data/lab.js` (lazy) |
| `writing/phrases.json` | phrase bank: `groups → phrases { id, text (Polish), en, level, register, example, note, genres }` (from B1) | `data/phrases.js` (lazy) |
| `exams/registry.json` | exams (stage E, spec 12); fields include `accent`, `accent2`, `promptInTarget` | `data/exams-registry.js`, `data/exam-<id>.js` |

Markdown conventions (spec 05 §5): `*italics*` is Polish only and gets `lang="pl"` (English emphasis is `**bold**`); the cells of a table column headed “Polish” and blockquotes get `lang="pl"` and a listen button; `[[topic id]]` links to a topic (a “soon” chip when its level is not available).

## How to add…

**A topic page.** The topic must already be in `content/syllabus.json` (new syllabus ids need the owner's OK). Copy `docs/plan/examples/pages/a1/cases-accusative.md` to `content/pages/<level>/<category>-<slug>.md` (the topic id without the level prefix), keep the front matter `id`, `level`, `category`, `title`, `summary` and the section headings of spec 07 §1 for its category. Add the trail quiz `content/quizzes/<level>/<topic id>.json` (4 items). Run `npm run build`; the level page links the topic and the trail stop opens the quiz.

**An exercise set.** Write `content/exercises/<topic id>-<n>.json` (`version: 1`, `id`, `topic`, `level`, `title`, `items` with ids `<set id>-NN`, 8–12 items, at least four item types for grammar topics), list it under its topic in `content/exercises/topics.json`, run `npm run build`. Practice, the topic page (“Check yourself”) and the Case Lab (“Practice this case”, through `tags`) pick it up.

**A deck.** Write `content/decks/<id>.json` (`version`, `id`, `title`, `description`, `level`, `cards[]` with ids `<deck id>-NNN`) and add an entry with `file` and `count` to `content/decks/index.json`; run `npm run build`.

**A level.** All six levels and their topics already exist in the syllabus as “soon”. Write the level's content (topic pages, quizzes, sets, `summaries/<level>.md`, `cheatsheets/<level>.md`, `tests/final-<level>.json`, its placement questions), then set the level to `"available"` in `content/levels.json`. `npm run validate` refuses an available level that is not complete (spec 10 §7); `node tools/cheatsheets-pdf.js <level>` checks the cheat sheet fits one page.

Every content change goes through the quality gate of spec 10: validators green, a solver review without the key (`npm run strip-keys`) and a native proofreader review.

## Language layer

Polish-specific code lives only in `js/lang.js` (`LM.lang`: diacritics, folding, answer normalising, word count, abbreviations, case names and question words) and `js/config.js` (`LM.APP`: app names, storage prefix, voices, the character bar, report links). `npm run check:lang` enforces it.

- **Answers.** `LM.exLogic.match` checks every typed answer (exercises and flashcards): exact → accents only → wrong ending → typo → word diff; a near miss scores 0 with a hint. The learning setting “Accept answers without accents” counts accent-only answers.
- **Character bar** (`js/charbar.js`) under every Polish input: ą ć ę ł ń ó ś ź ż; Shift or a long press for capitals; Alt + letter cycles the marked forms.
- **Speech** (`js/speech.js`, `LM.speech`): pl-PL voices only. Without a Polish voice the listen buttons are hidden, listening items show the transcript and dictation is skipped.

## Report a mistake

Topic pages, set and quiz results and content flashcards have a “Report a mistake” link to `LM.APP.reportUrl` (a new GitHub issue with the item id in the title); `LM.APP.reportMail` adds a `mailto:` alternative.

## Version stamp

`package.json` → `"lmVersion"` is the only source. The build writes it as `?v=N` on every local `<script>` and `<link>` in `index.html` and as `LM.VERSION`; `LM.loadModule(path)` adds it to files loaded on demand. Raise it with `npm run build -- --bump` before publishing, so browsers fetch the new files.
